# 质量检查清单

H5 心理测试的质量检查标准，确保输出内容有趣、准确、可用。

## 内容质量检查

### 题目质量

- [ ] **有趣度**：题目是否能引发用户的好奇心和参与欲？
- [ ] **场景感**：题目是否有具体的场景，而非空泛的提问？
- [ ] **共鸣度**：目标用户能否在题目中看到自己的生活影子？
- [ ] **无引导性**：题目是否避免了明显的社会期望导向？

**检查方法：**
- 朗读题目，看是否顺口自然
- 想象自己是目标用户，是否愿意回答
- 检查是否有"正确答案"暗示

### 选项质量

- [ ] **具体性**：选项是否描述了具体行为/场景，而非抽象特质？
- [ ] **区分度**：各选项之间是否有明显的差异？
- [ ] **人格指向**：每个选项是否对应明确的人格维度？
- [ ] **平衡性**：选项是否覆盖了不同的人格类型？
- [ ] **趣味性**：选项表达是否生动有趣？

**检查方法：**
- 遮住题目，只看选项能否猜出题目类型
- 检查是否有选项明显"更好"或"更差"
- 确保每个选项都有人可能选择

### 结果质量

- [ ] **准确性**：结果描述是否与题目逻辑一致？
- [ ] **洞察性**：结果是否点出了用户可能没意识到的特质？
- [ ] **积极性**：结果是否以积极的方式呈现（即使指出缺点）？
- [ ] **记忆点**：结果名称是否有特色，容易被记住？
- [ ] **分享欲**：用户是否愿意把这个结果分享出去？

**检查方法：**
- 模拟不同答题路径，检查结果是否合理
- 检查每种结果是否都有达成路径
- 评估结果的"社交货币"价值

### 结果可达性

- [ ] **路径覆盖**：每种结果是否都有合理的答题路径？
- [ ] **分布均衡**：各结果的达成难度是否相近？
- [ ] **无僵尸结果**：是否存在几乎无法达成的结果？
- [ ] **无垄断结果**：是否存在过于容易达成的结果？

**检查方法：**
- 列出每种结果的达成条件
- 模拟 10 组不同答案，检查结果分布
- 确保最极端的答案也能得到合理结果

## 视觉质量检查

### 整体视觉

- [ ] **风格一致性**：所有页面是否保持统一的视觉风格？
- [ ] **主题契合**：视觉风格是否与测试主题相符？
- [ ] **品牌感**：是否有独特的视觉识别度？

### 配色

- [ ] **和谐度**：配色是否协调，不刺眼？
- [ ] **对比度**：文字与背景对比度是否足够（WCAG AA）？
- [ ] **情绪匹配**：配色是否传达了正确的情绪氛围？
- [ ] **主辅平衡**：主色、辅助色、强调色比例是否恰当？

### 排版

- [ ] **层级清晰**：标题、正文、注释的层级是否分明？
- [ ] **可读性**：字体大小是否适合移动端阅读？
- [ ] **对齐统一**：元素对齐是否一致？
- [ ] **留白适当**：是否有足够的呼吸空间？

### 图像

- [ ] **清晰度**：图片是否清晰，无模糊或拉伸？
- [ ] **风格统一**：所有图片是否保持统一的绘制风格？
- [ ] **相关性**：图片是否与内容相关？
- [ ] **加载优化**：图片是否经过压缩优化？

## 交互质量检查

### 答题流程

- [ ] **流程完整**：从首页到结果页的流程是否顺畅？
- [ ] **进度感知**：用户是否清楚当前进度？
- [ ] **返回修改**：是否可以返回修改之前的答案？
- [ ] **状态保持**：意外退出后是否能恢复进度？

### 反馈机制

- [ ] **选中反馈**：选择选项后是否有明确的视觉反馈？
- [ ] **过渡动画**：页面切换是否有平滑的过渡？
- [ ] **加载提示**：等待时是否有加载动画或趣味文案？
- [ ] **错误处理**：出错时是否有友好的提示？

### 适配性

- [ ] **响应式**：是否适配不同尺寸的移动设备？
- [ ] **触摸友好**：按钮和选项是否足够大，易于点击？
- [ ] **性能流畅**：动画是否流畅，无卡顿？

## 功能质量检查

### 核心功能

- [ ] **计分准确**：结果计算逻辑是否正确？
- [ ] **随机性**：需要随机时是否真正随机？
- [ ] **边界处理**：极端情况（如全部选A）是否处理？

### 分享功能

- [ ] **结果分享**：是否可以分享结果？
- [ ] **海报生成**：海报是否正常生成？
- [ ] **预览优化**：分享时的预览图和文案是否吸引人？
- [ ] **链接可用**：分享链接是否能正常打开？

### 数据追踪

- [ ] **答题数据**：是否可以统计答题数据？
- [ ] **结果分布**：是否可以查看各结果的分布情况？

## 用户体验检查

### 首次体验

- [ ] **3秒规则**：3秒内能否理解这是什么测试？
- [ ] **参与动机**：首页是否激发了参与欲望？
- [ ] **门槛适中**：开始测试的门槛是否足够低？

### 答题体验

- [ ] **节奏适中**：答题节奏是否舒适，不紧不慢？
- [ ] **认知负荷**：每题的认知负荷是否适中？
- [ ] **趣味性**：答题过程是否有趣，不枯燥？

### 结果体验

- [ ] **期待满足**：结果是否符合用户的期待？
- [ ] **惊喜元素**：结果中是否有意外的洞察？
- [ ] **行动引导**：是否有明确的下一步引导（分享、重测）？

## 技术质量检查

### 代码质量

- [ ] **结构清晰**：代码结构是否清晰，易于维护？
- [ ] **注释充分**：关键逻辑是否有注释？
- [ ] **无冗余**：是否有重复或无用代码？

### 性能

- [ ] **加载速度**：首屏加载时间 < 3 秒
- [ ] **资源优化**：图片、CSS、JS 是否优化？
- [ ] **内存管理**：是否有内存泄漏风险？

### 兼容性

- [ ] **浏览器兼容**：是否兼容主流移动端浏览器？
- [ ] **微信兼容**：在微信内置浏览器是否正常？
- [ ] **降级处理**：旧设备是否有降级方案？

## 检查流程

1. **自测**：开发者自己完成测试，检查明显问题
2. **交叉检查**：让同事/朋友测试，收集反馈
3. **数据验证**：上线后观察数据，验证结果分布
4. **迭代优化**：根据反馈和数据持续优化

## 通过标准

**必须满足（P0）：**
- 所有功能正常可用
- 结果计算准确
- 无明显视觉问题
- 移动端适配良好

**应该满足（P1）：**
- 内容有趣，有共鸣
- 视觉统一，有美感
- 交互流畅，体验好

**最好满足（P2）：**
- 结果有洞察，有惊喜
- 分享率高
- 用户愿意重测
