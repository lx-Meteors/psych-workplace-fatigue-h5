# H5 心理测试生成器

将用户需求转化为完整的 H5 心理测试页面。

## 工作流程

### 阶段 1：需求结构化（自动执行）

用户输入需求背景后，自动拆解为以下维度：

| 维度 | 说明 | 示例 |
|------|------|------|
| 主题 | 测试核心主题 | "你是什么类型的猫？" |
| 视觉风格 | 整体美术风格 | 可爱插画风、极简现代风、复古像素风 |
| 配色方案 | 主色+辅助色 | 暖橙+米白、冷蓝+银灰 |
| 页面元素 | 装饰性元素 | 猫咪插画、几何图形、粒子效果 |
| 交互方式 | 答题交互模式 | 点击选项、滑动选择、拖拽排序 |
| 题目数量 | 建议 5-12 题 | 根据主题复杂度调整 |
| 结果类型 | 结果分类方式 | 4-8 种人格/类型 |

**执行步骤：**
1. 分析用户需求，提取关键词
2. 从 `references/visual-styles.md` 加载视觉风格库
3. 从 `references/color-schemes.md` 加载配色方案库
4. 生成 3 套推荐方案供用户选择
5. 等待用户确认或修改

### 阶段 2：内容生成（自动执行）

用户确认方案后，生成：

1. **题目与选项**
   - 题目必须贴合主题，避免空泛
   - 每个选项必须对应特定人格倾向
   - 选项设计要有趣、有画面感
   - 参考 `references/question-patterns.md`

2. **结果人格**
   - 生成 4-8 种结果类型
   - 每种结果包含：名称、描述、特征标签、匹配度说明
   - 结果要有区分度，避免过于相似

3. **计分规则**
   - 设计维度计分逻辑
   - 确保结果可达（每种结果都有路径）
   - 避免所有用户都落到同一种结果

### 阶段 3：页面开发（自动执行）

生成 5 个页面的完整代码：

| 页面 | 功能 | 关键元素 |
|------|------|----------|
| 首页 | 吸引用户进入 | 标题、主题图、开始按钮、规则说明 |
| 答题页 | 展示题目和选项 | 进度条、题目、选项、上一题/下一题按钮 |
| 加载页 | 过渡动画 | 加载动画、趣味文案 |
| 结果页 | 展示测试结果 | 结果名称、描述、特征、匹配度、分享按钮 |
| 海报页 | 生成分享图片 | 结果卡片、二维码、品牌信息 |

**技术要求：**
- 使用 `assets/template/` 作为基础模板
- 响应式设计，适配移动端
- 支持返回修改答案
- 本地存储答题进度

### 阶段 4：质量检查（自动执行）

对照 `references/quality-checklist.md` 进行检查：

**内容质量：**
- [ ] 题目是否有趣？能否引发用户共鸣？
- [ ] 选项是否空泛？是否有明确的人格指向？
- [ ] 结果描述是否准确？是否有记忆点？
- [ ] 结果分布是否均衡？是否每种结果都可达？

**视觉质量：**
- [ ] 配色是否符合主题氛围？
- [ ] 字体层级是否清晰？
- [ ] 动画是否流畅自然？

**交互质量：**
- [ ] 答题流程是否完整？
- [ ] 返回修改功能是否正常？
- [ ] 分享功能是否可用？

## 使用方法

### 快速开始

用户只需描述需求：

> "我想做一个测试，看看用户是什么类型的咖啡"

然后按以下流程执行：

1. **分析需求** → 拆解主题、风格、题目数量等
2. **展示方案** → 提供 3 套视觉+交互方案供选择
3. **生成内容** → 创建题目、选项、结果
4. **开发页面** → 输出完整 H5 代码
5. **质量检查** → 验证内容、视觉、交互

### 用户可配置项

在方案展示阶段，用户可以：
- 选择视觉风格（从推荐方案中选择）
- 调整配色方案
- 修改题目数量
- 调整结果类型数量

### 交互模式

**答题交互支持两种模式：**

1. **即时跳转模式**（默认）
   - 用户选择选项后立即进入下一题
   - 适合快速完成的测试

2. **确认跳转模式**
   - 用户选择后需点击"下一题"按钮
   - 适合需要思考的心理测试

**返回修改：**
- 显示"上一题"按钮
- 保存已选答案，用户可修改

## 设计原则

### 题目设计

**好的题目：**
- 有场景感："周末早上醒来，你首先会..."
- 有画面感："你面前有三条路，你会选择..."
- 有情感共鸣："当朋友向你倾诉烦恼时，你会..."

**避免：**
- 空泛的问题："你觉得自己是个什么样的人？"
- 过于明显的倾向："你喜欢帮助别人吗？"
- 文化壁垒：需要特定知识背景才能理解

### 选项设计

**好的选项：**
- 具体行为描述，而非抽象特质
- 每个选项对应明确的人格维度
- 选项之间要有区分度

**示例：**
```
❌ 不好：A. 外向  B. 内向
✅ 好：A. 立刻加入大家的讨论  B. 先在一旁观察
```

### 结果设计

**好的结果：**
- 名称有记忆点："温暖治愈系大橘猫"
- 描述有洞察：点出用户没意识到的特质
- 有社交货币：用户愿意分享的结果

## 注意事项

1. **结果可达性**：确保每种结果都有合理的达成路径，避免"僵尸结果"
2. **题目数量**：5-12 题为最佳，太少缺乏准确性，太多用户流失
3. **视觉一致性**：所有页面保持统一的视觉语言
4. **性能优化**：图片压缩、代码精简，确保加载速度
5. **分享优化**：结果页要有吸引力的分享文案和预览图
